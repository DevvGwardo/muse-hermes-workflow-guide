01

connect with tailscale

Install Tailscale and sign in with the same account on both sides. Open Tailscale on the desktop and note its MagicDNS name.

It looks like the placeholder below. Keep it private. Never publish this address or post it in public.

https://YOUR-DESKTOP.<tailnet>.ts.net

Check:
- Desktop shows as online in Tailscale
- You use the same account on both sides
about 3 minutesdifficulty: easy
Common mistake: Skipping the same account check. If the two sides use different Tailscale accounts, they will never see each other.
02

pair hermes duet

Open Hermes Duet on the desktop and ask for a pairing code. Use it right away, because it expires after 10 minutes.

Pair once, save the session cookie to a private file, and set tight permissions. If you see 401 not paired, get a fresh code and pair again. Never share the cookie.

POST /api/pair
Body: { "code": "YOUR-PAIRING-CODE" }

# save the returned cookie in a private file
# example file name: cookies.txt
chmod 600 cookies.txt
about 4 minutesdifficulty: easy
Common mistake: Waiting too long to use the code. Pairing codes expire after 10 minutes, so pair right away and keep the cookie file private.
03

add the bridge

Add a small Python bridge that talks to the Hermes Duet API. It uses only the standard library and your private address.

Key endpoints are GET /api/state to list channels and items, and POST /api/messages with text and channel_id to send. The default channel is chan-general.

python3 bridge.py state
python3 bridge.py send chan-general "hello from Muse"
python3 bridge.py fetch chan-general
# bridge.py - tiny sketch, standard library only
import json, urllib.request, pathlib

BASE = "https://YOUR-DESKTOP.<tailnet>.ts.net"
COOKIE = pathlib.Path("cookies.txt").read_text().strip()

def call(path, data=None):
    req = urllib.request.Request(BASE + path,
        data=json.dumps(data).encode() if data else None,
        headers={"Cookie": COOKIE, "Content-Type": "application/json"})
    with urllib.request.urlopen(req) as r:
        return json.loads(r.read())

# list channels: call("/api/state")
# send a note: call("/api/messages", {"channel_id": "chan-general", "text": "hello"})
example demo - placeholder values only
Pick a button above. The command types itself here, then shows short example output. Nothing real runs.
about 6 minutesdifficulty: medium
Common mistake: Hardcoding a real address into the bridge. Keep the placeholder shape, swap in your own private address locally, and never publish it.
04

add the watcher

Run a check script every 5 minutes. It fetches /api/state, compares item ids with last_seen.json, and reports only new items from Hermes.

Count kinds agent, assistant, and activity, plus user messages that are not your own. Mark your own sends so the watcher skips them.

# cron idea: run every 5 minutes
*/5 * * * * python3 check.py

# dedup rule that matters most:
# when you fetch one channel, MERGE new ids into last_seen.json
# never overwrite the file with only that channel
# if you overwrite, old messages from other channels look new again
Read that dedup rule twice. Most repeat message bugs come from overwriting last_seen.json. Always merge.
about 4 minutesdifficulty: medium
Common mistake: Overwriting last_seen.json with one channel only. Always merge new ids in, or old messages from other channels look new again.
05

send your first handoff

Use this template. Say the task, the files, what done looks like, and ask Hermes to report back in the same channel.

Task: [one clear job]
Files or paths: [exact paths]
Done means: [what success looks like]
Please report back in this channel with:
- what changed
- file paths
- how you checked it
- anything that still needs me

A good Hermes reply looks like this: Done. Changed 2 files at src/app.py and tests/test_app.py. Tests pass, 24 of 24. Nothing needs you, except a quick look at the new wording.

about 2 minutesdifficulty: easy
Common mistake: Sending a vague first job. Name the task, the exact paths, and what done looks like, or the reply will be hard to check.
06

make it a habit

Morning: Muse checks overnight Hermes reports and gives you one short brief. Midday: one handoff at a time, so nothing collides.

Evening: Hermes reports, Muse summarises for you. One job at a time per channel. One clear owner per task. That rhythm keeps it calm.

morning  - Muse checks overnight reports
midday   - one handoff at a time
evening  - Hermes reports, Muse summarises
about 1 minutedifficulty: easy
Common mistake: Running two jobs in one channel at once. One job at a time per channel keeps reports clear and avoids collisions.

- house rules

the house rules.

These keep the workflow safe and easy to trust.

you outrank both agents

If you say stop, both stop. If you say wait, both wait. No debate.

outward steps need approval

Sends, posts, payments, and publishes need you plus an approval first. Drafts are fine. Sending is not automatic.

never send secrets in chat

Never send passwords, API keys, or tokens through chat, in either direction. Use a proper vault or local file instead.

research needs receipts

Every research claim needs a URL, a quote, and a timestamp. No receipt, no claim.

context travels as a file

Share context as a readable file path with provenance. Never pass a paraphrased fact as if it were the source.

unsure means ask

If either agent is unsure, it asks and waits. A short pause beats a wrong action.

- when it breaks

when it breaks.

Most fixes take two minutes. Try the one fix for your row first.

desktop offline

Fix: Check power, check Tailscale is online, and check Hermes Duet is running. Then resend once.

Extra check: open Tailscale on the desktop and confirm this device shows as connected, then open Hermes Duet before you resend.

401 not paired

Fix: Get a fresh pairing code in Hermes Duet and pair again. Old codes expire after 10 minutes.

Extra check: codes last 10 minutes. If pairing still fails, close and reopen Hermes Duet, then ask for a brand new code.

watcher repeats old messages

Fix: Restore the full id list in last_seen.json and switch to merge, not overwrite. See step 4.

Extra check: open last_seen.json and confirm it holds ids from every channel, not just chan-general.

no reply

Fix: Check the channel id is chan-general, check Hermes is running, then resend once and wait.

Extra check: confirm the message appears in the channel in Hermes Duet. If it does, Hermes may be mid job, so wait for a status.

slow or stuck job

Fix: Ask Hermes for a one line status. Do not send duplicates, or you will create two jobs.

Extra check: long builds can run for hours. A single status ask is enough; duplicates create extra work.

desktop slept mid job

Fix: Wake the desktop, confirm Hermes Duet is open, and ask for a status before you resend anything.

Extra check: for long jobs, set the desktop to stay awake while plugged in, then confirm Hermes Duet stayed open.

no matches, try another word. try: paired, sleep, watcher, offline, channel, stuck.
